# Portfolio Site QA 안내

검토일: 2026-10-09 · 제품 QA 진입점

2026-10-09 사용자 요청으로 앱마다 흩어진 안내·결과·도구 위치를 통일했다. 이 문서는 실행과 자료 탐색을 소유하고, 최종 결과는 작업별 리포트에 기록한다.

## 1. 적용 지침

포트폴리오의 `docs/QA_REPORT_STANDARD.md`(QR), `docs/APP_VISUAL_QUALITY_STANDARD.md`(VQ), `docs/NEW_APP_DEVELOPMENT_GUIDE.md` §12를 따른다. 릴리스 명령·기기 E2E·Release smoke는 `control-plane/app-release-hub/docs/governance/QA_STANDARD.md`를 따른다. 정책 원문을 제품에 복제하지 않는다.

- 작은 수정은 영향 화면·상태·해당 테마만 확인한다. 첫 출시·공통 테마·탐색 구조·광범위 개편은 VQ 전수 점검을 적용한다.
- 최대 글자 크기 및 그 최대값을 모사하는 확대 조건은 설계·실행·완료 조건에서 제외한다. 과거 기록은 당시 증거로만 보존한다.
- 자동 검사·실제 사용자 흐름·기기·운영 API·배포·스토어 공개를 구분한다.

## 2. 제품 표면과 테스트 자료

현재 [앱 계약](../app.contract.json)의 runtime을 기준으로 한다. 제공하는 기능의 소비 표면을 함께 확인하고, 미반영 표면은 이유와 반영 조건을 기록한다.

| 표면 | 실행 위치 | 프레임워크 | 테스트 소스 탐색 위치 |
| --- | --- | --- | --- |
| web | `.` | vite | `src` |

## 3. 자동 검사

대상 제품 저장소 루트에서 선언된 패키지 관리자와 도구 버전으로 실행한다. 전체 게이트와 변경 범위별 검사를 구분하며, 명령의 존재만으로 통과를 주장하지 않는다.

```sh
pnpm check
pnpm docs:check
```

명령 원본은 [package.json](../package.json)과 [앱 계약](../app.contract.json)이다. 전체 게이트가 빌드·DB·외부 환경을 필요로 하면 먼저 자원과 설정을 확인한다. 문서만 바꾸는 작업은 문서·링크 검사로 확인하며 제품 QA를 실행했다고 보고하지 않는다.

## 4. 사용자 흐름과 탐색 QA

기존 개발 서버·앱·기기에 붙는다. QA 준비를 위해 제품 DB를 새로 만들거나 초기화하지 않는다. Expo 반복 UI 확인은 runtime 루트의 `expo start`, Flutter는 debug 구성을 사용한다. 서버가 있는 제품은 로컬 개발 API와 실제 앱 API 주소·개발 로그인 상태를 확인한다.

iOS는 이미 실행 중인 Device Hub 기기(iPhone 17 Pro · iOS 26.5 기본)를 사용하고 새 기기를 만들거나 추가 부팅하지 않는다. Device Hub를 `cua_repl`로 읽거나 조작하지 않는다. 자동 host 연결이 실패하면 수동 검증 범위와 한계를 기록한다.

ExploreQA 실행 adapter는 현재 미구비다. 안내 파일이나 일반 자동 테스트를 탐색 캠페인 완료 증거로 쓰지 않는다. 기존 개발 대상에서 사용자 흐름을 수동으로 검증하고 리포트에 기록한다.


## 5. 결과 기록과 자료 위치

| 자료 | 통일 위치 | 소유 범위 |
| --- | --- | --- |
| 현재 QA 안내 | 이 문서 `docs/QA.md` | 범위·실행·자료 찾기 |
| 결과 색인 | [docs/qa/README.md](qa/README.md) | 작업별 결과와 과거 기록 탐색 |
| 최종 리포트 | `docs/qa/YYYY-MM-DD-작업명.md` | 판정·대상·환경·재현·수정 전후·미확인·보관 |
| 작성 템플릿 | [docs/templates/QA_REPORT.md](templates/QA_REPORT.md) | QR 일곱 항목. 포트폴리오 템플릿의 동일 사본 |
| 재사용 QA 도구 | `tools/qa/` 및 runtime 테스트 소스 | adapter·페르소나·회귀 fixture·검사 도구 |
| 계약 증거 | `docs/evidence/` | 소비 계약이 지정한 경로·digest·acceptance 증거 |
| 제품 디자인·설계 기록 | `docs/design/` 등 | 제품 결정·시각 감사·발표 자료. QA 최종 판정은 리포트 참조 |

같은 작업의 재검증은 한 리포트에 합친다. 실행 중 임시 출력은 저장소 밖을 기본으로 하고, 기존 adapter가 요구하는 Git-ignored 출력은 종료 시 리포트 대조 후 제거한다. 이미지·영상·JSON·전체 로그를 리포트에 덤프하지 않는다.

## 6. 완료와 보관

일곱 항목을 채우고 실패·미확인·후속 조건을 보존한 뒤 링크와 보관 처리를 확인한다. 계약 증거는 소비자와 digest를 함께 갱신하기 전에는 이동·삭제하지 않는다. `planned` 자료와 정리 시점 HEAD는 실제 검사 증거가 아니다. 개발 Mac에서 버전을 올리거나 배포 설정을 바꾸지 않으며, 릴리스는 제품 SHA·QA 경로·환경 이름·migration 목록과 필요한 새 OS Release 첫 실행 기록을 mac-ci로 인계한다.
