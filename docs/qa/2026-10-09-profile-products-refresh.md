# QA 리포트 — 제품 정보 최신화·마케팅 사례 통합

## 1. 최종 판정

로컬 코드·검사·명시한 브라우저 범위 통과. 공개 배포·사이트 push는 사용자 지시로 실행하지 않았다.

## 2. 대상과 이력

Portfolio Site main, 기준 43d7ad9. 영향 표면은 이 독립 웹 제품의 정적 소개·자산·정책 URL 투영이다.
앱·서버·공용 계약·제품 버전·CI·배포 설정은 바꾸지 않는다. 시작 시 main은 clean이었다.

## 3. 환경과 범위

개발 Mac, Node 24.20.0, pnpm 11.24.0. Codex 인앱 Chromium의 로컬 Vite dev 서버를 사용했다.
기본 데스크톱과 390×844px에서 제품·마케팅 카드 및 메뉴 이동을 확인했다.
OS 최대 글자와 그 최대값을 모사하는 조건은 범위에서 제외한다.

## 4. 수정 전후

- 기존 아이콘 4개가 제품 launcher와 달랐다. 현재 원본 7개를 바이트 그대로 투영하고 SHA-256을 기록했다.
  경로·동기화·snapshot 경계는 [앱 자산 원천](../APP_ASSETS.md)에 있다. Taground는 보관된 원본을 유지한다.
- 누락된 Diairy·Spint·Utilverse를 추가했다. Utilverse는 개발 중, Spint는 확인한 iOS만 연결한다.
  비행중 Android 링크도 추가했다. 카드 제목의 동일한 영문 이름 중복을 없앴다.
- Diairy app-owned 법률 링크가 중앙 policy.json 없이도 생성되도록 고쳤다. 공개 URL만 투영한다.
- 사용자가 별도 포슬이 영역을 없애고 브랜딩 운영을 마케팅 전략에 설명하도록 요청했다.
  메뉴·그림 파일·소개 구역·중복 앱 카드·전용 socialHook·사용하지 않는 문구를 제거했다.
  마케팅 전략과 크게 보기 도식에 공통 캐릭터·@posli.makes·일상툰·앱 소개툰 운영과 릴스 제작·검수를 넣었다.
  중앙 marketing/GUIDE.md가 운영 원문이며 미확인 홍보 성과와 릴스 게시 완료를 주장하지 않는다.

초기 build는 Diairy가 정책 투영 목록에 없어 type 오류로 실패했다. 투영 조건과 회귀 검사를 고친 뒤 통과했다.
문서 검사도 아직 만들지 않은 QA 리포트 링크 때문에 한 번 실패했고 해당 리포트 작성 후 전체 검사 통과했다.
GitHub 이미지의 로드 직후 관찰은 pending이었으며 로드 완료 후 전체 이미지 표시를 확인했다.
HTTP 응답·스토어 레코드는 앱 내부 기능이나 설치·가입 흐름의 성공 증거가 아니다.

## 6. 미확인 범위

공개 배포·실제 공개 사이트 반영은 제외했다. Pages가 legacy main 루트를 소비하므로 사이트 push도 하지 않는다.
사용자는 배포를 다른 계정에서 하며 이번 작업은 코드 수정만 하라고 지정했다.
모든 브라우저·실기기·소셜 외부 링크 수정·성과 계측·새로운 스토어 심사/출시는 검사하지 않았다.
공통 디자인 전체 테마·전체 제품 화면 QA를 새로 수행한 것으로 주장하지 않는다.

## 7. 보관·정리

이 리포트에 결과·실패·수정·미확인 범위를 통합했다. 임시 로그·JSON·중간 캡처와 작업 스크립트는 제거한다.
사용자에게 보여 주는 최종 GitHub·마케팅 화면 이미지만 Documents/Codex의 발표 산출물로 보존한다.
제품 원본·사용자가 제공한 사진·과거 .published 게시 산출물은 보존한다.
새 브랜치·워크트리·clone을 만들지 않았으며 이 repo의 작업용 브랜치·워크트리도 없다(main 하나).
자체 Vite 개발 서버만 종료하고 다른 앱의 기존 실행 자원은 유지한다.
