# HJM 1.15.0 소비 적용 — Portfolio Site

## 1. 최종 판정

게시된 의존성·계약·잠금 파일 갱신과 로컬 canonical 검사 통과. 실제 브라우저 UI·공개 배포는 미확인이다. 마지막 확인: 2026-10-07T22:22:14+09:00.

## 2. 대상과 이력

독립 worktree의 `codex/hjm-1.15-consumer-20261007`, baseline `13438cd5b1427262d2929a244ff2ab05ab883eee`에 이 작업의 미커밋 변경만 포함해 검사했다. 수행자: Codex. 공유 제품 checkout의 기존 변경과 실행 중인 개발 서버는 건드리지 않았다. 공개 HJM 출처는 `v1.15.0`/`9aa33e2063dc65d0427697fb5a20b48ab7cba387`이다.

## 3. 환경과 검증 범위

Node 24.20.0, pnpm 11.24.0, macOS. 공식 npm exact contracts/React renderer 1.15.0을 lifecycle scripts 없이 frozen 설치했다. Vite 7.3.6 production bundle은 로컬 산출물이며 게시하지 않았다. 브라우저·기기·API·계정 시나리오는 실행하지 않았다. OS 최대 글자와 이를 모사하는 확대 검사는 범위에서 제외했다.

## 4. 결과·문제와 수정

- 중앙 release record에서 카탈로그 두 사본과 integrity 기록을 `sync-standard` dry-run 검토 후 투사했다. 두 카탈로그 SHA-256은 `5d13c477d342ac599e480cbfcbf6df4414a28a3ba775a3cc0a30adc8cc07f428`이다.
- 초기 lock 재생성은 old 1.14.0 lock의 선행 냉각 검사에서 실패했다. 기존에 검증된 old exact 예외를 재생성 단계에만 함께 유지하고, 재생성 직후 old 예외를 제거했다. namespace 예외·정책 완화·잠금 파일 수동 병합은 사용하지 않았다. 최종 1.15.0-only 예외와 frozen 설치는 통과했다.
- 설치된 두 package 버전과 공식 npm metadata integrity/중앙 record 일치를 확인했다. HJM 외 lock의 package version 변경은 없고 HJM peer resolution만 1.15.0 train으로 이동했다.
- 설치된 공개 `defineHjmDesignProfile`로 paper를 확장해 radius.md=29, collection=rows, overview=editorial의 앱 소유 override가 보존됨을 확인했다. 이 검사는 제품 화면이 해당 profile을 채택했다는 주장이 아니다. 기존 제품 브랜드 source는 변경하지 않았다.
